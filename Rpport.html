1. Présentation du projet

Dans le cadre du projet intégrateur 2025-2026 de l'Institut de Formation et de Recherche en Informatique (IFRI), notre équipe a développé une application web dénommée IFRI_MentorLink.

Cette plateforme a pour objectif de faciliter la mise en relation des étudiants souhaitant bénéficier d'un accompagnement académique avec ceux disposés à partager leurs connaissances et leurs compétences. Elle constitue ainsi un espace d'échange et de collaboration favorisant l'entraide entre les membres de la communauté estudiantine de l'IFRI.

L'application permet à chaque utilisateur de créer un profil personnalisé contenant notamment ses compétences, ses domaines de maîtrise, ses besoins d'accompagnement ainsi que ses disponibilités. Les étudiants peuvent ensuite publier des offres ou des demandes de mentorat selon leurs objectifs.

Afin d'accroitre l'expérience utilisateur, un système de mise en correspondance analyse les informations fournies by les utilisateurs et propose automatiquement les profils les plus pertinents. Une messagerie intégrée permet également aux mentors et mentorés de communiquer facilement et d'organiser leurs séances d'accompagnement.

À travers ce projet, nous avons mis en pratique les connaissances acquises au cours de notre formation, notamment en développement web, en conception de base de données et en programmation asynchrone.

3. Organisation et méthodologie de travail

Pour mener ce projet à terme dans les délais impartis, nous avons choisi de segmenter les différentes tâches dès le coup d'envoi. Cette organisation modulaire a permis de travailler simultanément sur les couches Frontend, Backend et Base de données.

Tout au long du cycle de développement, nous avons utilisé les systèmes de contrôle de version Git et GitHub pour centraliser notre code, suivre les modifications et résoudre les conflits d'intégration. Chaque participant a opéré sur des branches thématiques dédiées avant de fusionner son code après revue par les pairs.

Des points de synchronisation réguliers nous ont permis de suivre l'état d'avancement, de lever les blocages techniques et d'ajuster l'algorithme de matching au besoin. Cette communication continue a été la clé de voûte de notre réussite collective.

4. Architecture du système

L'application IFRI_MentorLink est conçue selon une architecture Client-Serveur découplée. Cette approche garantit une excellente séparation des préoccupations, simplifiant la maintenance corrective et les évolutions futures.

  • La partie cliente (Frontend) : Constituée d'interfaces web dynamiques développées en HTML5, CSS3 et JavaScript. Elle gère les interactions des utilisateurs (inscription, gestion des profils, recherche et chat en temps réel).
  • La partie serveur (Backend) : Développée en Python via le framework Flask. Elle orchestre la logique métier, l'authentification sécurisée, l'exécution de l'algorithme de correspondance et les appels à la base de données.
  • La persistance des données : Repose sur un système de gestion de base de données relationnelle PostgreSQL, qui assure l'intégrité et la robustesse du stockage.

5. Base de données

La base de données de l'application IFRI_MentorLink a été entièrement modélisée et implémentée sous PostgreSQL afin de garantir la cohérence transactionnelle et une parfaite intégrité référentielle. Elle centralise les données requises par les différentes briques applicatives.

L'architecture relationnelle s'appuie sur dix tables interconnectées :

  • users : Stocke les identifiants d’authentification essentiels (nom, prénoms, e-mail unique, téléphone et mot de passe haché via bcrypt).
  • profiles : Regroupe les attributs de profil (filière, niveau d’études, biographie).
  • skills : Catalogue global des compétences et matières académiques disponibles.
  • user_skills : Table d’association gérant la relation plusieurs-à-plusieurs (Many-to-Many) entre les utilisateurs, leurs forces (mentors) et leurs besoins (mentorés).
  • availabilities : Enregistre les plages horaires globales des étudiants.
  • mentoring_posts : Contient les annonces ciblées d'offres et de demandes publiées.
  • post_availabilities : Fait le pont entre les annonces et les contraintes horaires spécifiques.
  • matches : Consigne l'historique des liaisons suggérées et validées par l'algorithme.
  • conversations & messages : Orchestrent les structures de données indispensables au fonctionnement de la messagerie instantanée.

6. Algorithme de matching

Le cœur de la valeur ajoutée d'IFRI_MentorLink réside dans son algorithme de correspondance automatisé. Pour chaque couple Mentor/Mentoré potentiel, le système évalue la pertinence de l'association sur une échelle de 0 à 100 points, pondérée comme suit :

  • Compatibilité des compétences (50 points max) : Analyse croisée entre les matières maîtrisées par le mentor et les lacunes exprimées par le mentoré. Plus l'intersection est grande, plus le score croît.
  • Compatibilité des disponibilités (30 points max) : Vérification de l'existence de plages communes. Les créneaux matchent s'ils correspondent au même jour et présentent une intersection horaire (chevauchement).
  • Proximité académique (20 points max) : Un bonus de points est alloué si les deux étudiants partagent la même filière à l'IFRI, combiné à un incrément si le mentor dispose d'un niveau d'études strictement supérieur au demandeur.

7. Interfaces utilisateur & Modules

7.1 Authentification et Gestion de Profil

Les interfaces d'inscription et de connexion valident les contraintes de sécurité en amont. À l'inscription, l'utilisateur est invité à renseigner son cursus (Filière, Niveau). Une fois authentifié, l'espace "Mon Profil" lui donne un contrôle complet sur la mise à jour dynamique de ses compétences et de son calendrier de disponibilités.

7.2 Messagerie instantanée

Le module de messagerie permet d'engager le dialogue dès qu'une correspondance est validée (clic sur le bouton "Contacter"). L'interface est scindée en deux panneaux : le volet latéral gauche récapitule les discussions en cours, tandis que la zone principale affiche le flux des messages et la zone d'envoi textuel. Le stockage est rendu persistant via les tables dédiées.

8. Guide officiel de déploiement

Cette section détaille la procédure standard pour installer, configurer et exécuter l'application IFRI_MentorLink sur un nouvel environnement de production ou de développement.

8.1 Prérequis système

Outil Version minimale Lien de téléchargement
Python 3.10+ https://www.python.org/downloads
PostgreSQL 18 https://www.postgresql.org/download
Git Version récente https://git-scm.com

8.2 Procédure d'installation

  1. Clonage du dépôt :

    Ouvrez votre terminal et récupérez les sources du projet :

    git clone https://github.com/miracleabh-oss/PIL1_2526_12.git
cd PIL1_2526_12
  2. Installation des dépendances logicielles :

    Installez l'ensemble des modules requis listés dans le fichier des spécifications (Flask, SQLAlchemy, bcrypt, Flask-SocketIO, psycopg2) :

    pip install -r requirements.txt
  3. Initialisation de la base de données :

    Ouvrez votre SQL Shell (psql), connectez-vous à votre instance locale et créez la base de données :

    CREATE DATABASE mentorlink;
\q
  4. Importation du schéma :

    Depuis votre terminal système (en dehors de psql), injectez le fichier DDL pour générer les structures des 10 tables :

    psql -U postgres -d mentorlink -f schema.sql

    Pour valider la bonne exécution, vous pouvez lister les tables générées à l'aide de la commande : psql -U postgres -d mentorlink -c "\dt"

  5. Injection des données de test (Seed) :

    Pour charger les comptes utilisateurs factices ainsi que les jeux de données de démonstration :

    psql -U postgres -d mentorlink -f seed.sql
  6. Configuration des accès à la base de données :

    Ouvrez le fichier config.py situé à la racine du projet et modifiez la variable du mot de passe avec votre configuration PostgreSQL locale :

    raw_password = 'votre_mot_de_passe_personnel'
  7. Lancement du serveur applicatif :

    Démarrez l'application Flask à l'aide du script d'entrée :

    python run.py

    Le serveur s'initialise et se met à l'écoute sur l'adresse suivante : http://127.0.0.1:5000

8.3 Résolution des anomalies courantes

  • Erreur : psql n'est pas reconnu comme commande externe : Le binaire de PostgreSQL n'est pas renseigné dans les variables d'environnement (PATH) de votre système. Utilisez le chemin absolu vers l'exécutable, par exemple sur Windows :
    "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -d mentorlink -f schema.sql
  • Erreur : ModuleNotFoundError : Un package Python est manquant ou n'a pas été installé dans le bon environnement virtuel. Relancez la commande d'installation générale : pip install -r requirements.txt.
  • Erreur : could not connect to server : Le serveur PostgreSQL local est éteint. Sous Windows, ouvrez l'utilitaire Services (services.msc) et démarrez manuellement le service nommé postgresql-x64-XX.

9. Manuel d'utilisation simplifié

  • Naviguez sur l'adresse locale http://127.0.0.1:5000 depuis votre navigateur.
  • Cliquez sur S'inscrire pour renseigner vos données de filière ou utilisez un compte du fichier d'initialisation (`seed.sql`).
  • Connectez-vous à l'aide de vos identifiants.
  • Mettez à jour vos matières fortes et faibles sur la page de profil.
  • Consultez l'onglet Matching pour visualiser la liste ordonnée des profils pertinents. Cliquez sur Contacter pour ouvrir un canal de messagerie instantanée sécurisé.

10. Difficultés rencontrées & Solutions apportées

Au cours du cycle de développement, plusieurs verrous techniques ont dû être levés. Le premier résidait dans l'alignement des structures de données relationnelles pour la mise en correspondance, résolu grâce à l'étroite collaboration sur l'implémentation PostgreSQL. La conception fine de l'algorithme a également demandé plusieurs itérations de calcul pour équilibrer le barème de points et éviter les résultats aberrants (comme le fait de pouvoir matcher avec soi-même). Enfin, la centralisation sur Git a nécessité une gestion rigoureuse des branches pour éviter les conflits de fusion lors du rassemblement des modules de routes.
